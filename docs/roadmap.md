# Roadmap

Each phase ends with working, tested software and updated documentation. A phase is not
started until the previous one's acceptance checks pass.

| Phase | Deliverables | Key infrastructure | Exit check |
| --- | --- | --- | --- |
| **1 Foundation** ✅ | Monorepo, Go API, PostgreSQL migrations, setup, passwordless email-code sign-in, company email domains, sessions, workspaces, roles, emailed invitations, member sidebar, audit log, web app, Electron shell, Compose files | PostgreSQL, Caddy, SMTP relay | API integration tests; web and desktop sign-in; cross-org isolation tests |
| 1.x Security ✅ ([phase-1x.md](architecture/phase-1x.md)) | Admin account disable, domain ownership verification (DNS TXT), HTML and Turkish/English emails, desktop packaging (signing needs the organization's certificate) | — | Disabled accounts cannot request codes |
| **2 Messaging** ✅ ([phase-2.md](architecture/phase-2.md)) | ✅ 2.1 channels, messages, edits, deletes, unread counts, live updates · ✅ 2.2 DMs and group DMs · ✅ 2.3 threads, reactions, mentions, pins · ✅ 2.4 presence, status, typing, notifications · ✅ 2.5 file attachments, files tab, message search · ✅ 2.6 channel archive, message retention | Live events from the API process (ADR-0008); attachments on the API server's disk (ADR-0009; object storage later, license review pending); Centrifugo or Redis only when running several API replicas | Two users chat in real time; revoked members stop receiving events |
| **3 Secure rooms** ✅ ([phase-3.md](architecture/phase-3.md)) | Open, protected and restricted rooms, Argon2id room passwords, expiring admissions, password rotation, revocation across messages/files/search/notifications/live events (media in Phase 4) | — (ADR-0010) | Unauthorized user with the right password is denied |
| **4 Voice & video** ✅ ([phase-4.md](architecture/phase-4.md)) | ✅ persistent voice rooms, push-to-talk, mute/deafen, per-user volume, video, screen share (desktop picker), moderation · ✅ 4.3 scheduled meetings: email invitations with calendar files (.ics REQUEST/CANCEL), join window (15 min before to 2 h after), organizer moderation, home "Yaklaşan toplantılar" card | LiveKit with built-in TURN (ADR-0011) | Two users talk through self-hosted LiveKit; voice survives navigation |
| **5 Projects & whiteboard** ✅ ([phase-5.md](architecture/phase-5.md)) | ✅ public and private projects, tasks with Kanban (drag and drop, also by keyboard), list and calendar views, filters, assignees, checklists, comments, activity, links to rooms and channels · ✅ sprints, editable workflows and labels · ✅ Excalidraw whiteboards with persistence, live editing and cursors | Excalidraw (MIT, self-hosted assets); live collaboration over the existing event stream, no Yjs (ADR-0015) | Two users edit one board; tasks assignable |
| **6 Developer features** | GitHub/GitLab/Gitea/Forgejo connections, PR/CI activity, task linking, VS Code presence extension (client done: [vscode-extension.md](architecture/vscode-extension.md), ADR-0013; works once the API accepts personal access tokens), personal access tokens | — | Git activity linked to a project; extension shares only opted-in fields |
| **7 Workspaces & knowledge** | Department visual workspaces (finance, management, design), widgets, Tiptap documents, wiki, version history | — | Finance widgets invisible to unauthorized roles |
| **8 AI assistant** (in progress) | ✅ worker ([ai-worker.md](architecture/ai-worker.md), ADR-0012): optional internal service with signed requests; transcription (faster-whisper, optional extra); meeting and channel summaries whose decisions and action items must cite their sources (enforced in code); permission-aware retrieval (pgvector, permission filter inside the SQL query); task suggestions that a person approves · API and web integration pending | Python FastAPI worker (`compose.ai.yml`), pgvector, Ollama/vLLM (optional) | Core features run with AI disabled |
| **9 AI agents** (in progress) | ✅ worker: research, developer, project, data, whiteboard and voice agents; bounded runs (steps, tool calls, time); tools act only through API callbacks with a per-run delegated token, no shell, file or network tools; destructive tools pause for an approval bound to the exact call, single use; every step audited · API callbacks, approvals UI and run records pending | Sandboxed workers | Destructive actions always require approval |
| **10 Hardening** | SSO (OIDC/SAML), ✅ load tests ([load-testing.md](architecture/load-testing.md): 1,000 live streams without a dropped event, p99 under 10 ms with 200 people online), ✅ backup, restore and restore-drill scripts ([backup-restore.md](deployment/backup-restore.md)), monitoring, signed auto-updates, production validation | Prometheus/Grafana (optional) | Documented restore verified on a clean host — same-host drills pass (2026-10-30); the clean-host run is pending |
